# PdfViewer

A virtualized, in-browser PDF viewer built on [pdfjs-dist](https://mozilla.github.io/pdf.js/).
It renders only the pages currently inside the viewport, supports a selectable text layer with
in-document search, and provides a configurable toolbar with zoom, page-jump, fit controls, and
download/print.

**pdfjs-dist is loaded lazily** — it is not part of the entry bundle and only fetches on first render.

```tsx
import { PdfViewer } from '@geomak/ui'
```

---

## Source types

`PdfViewer` accepts four source shapes via the `source` prop. Choose based on where your content comes from.

| Shape | When to use |
|---|---|
| `string \| URL` | Remote URL — the only mode that performs a network request. |
| `File \| Blob` | Local file from an `<input type="file">` or a `fetch` response blob. |
| `ArrayBuffer \| Uint8Array` | Programmatic bytes — e.g. generated by jsPDF or received from a WebSocket. No network. |

```tsx
{/* Remote URL */}
<PdfViewer source="https://example.com/report.pdf" />

{/* File from <input type="file"> */}
<PdfViewer source={fileInputRef.current.files[0]} />

{/* Programmatic bytes */}
<PdfViewer source={uint8ArrayBytes} />
```

For remote sources, pass HTTP headers or credentials via the `remote` prop:

```tsx
<PdfViewer
  source="https://api.example.com/report.pdf"
  remote={{ httpHeaders: { Authorization: `Bearer ${token}` } }}
/>
```

## Toolbar

The `toolbar` prop is either `false` (hide entirely) or an object where each key toggles an individual control.
All keys default to `true`.

| Key | Control |
|---|---|
| `pager` | Page-jump input and prev/next arrows |
| `zoom` | Zoom percentage display, +/− buttons, fit-width and fit-page toggles |
| `search` | Debounced in-document search bar (highlights all matches) |
| `download` | Download the source file |
| `print` | Print |

```tsx
{/* Show only navigation — no zoom, no search */}
<PdfViewer source={bytes} toolbar={{ pager: true }} />

{/* No toolbar — pure reading surface */}
<PdfViewer source={bytes} toolbar={false} />
```

## Text layer and search

When `textLayer` is `true` (the default), invisible `<span>` elements are overlaid on each page,
aligned to the PDF glyphs via the transform matrices supplied by pdfjs-dist. This makes text
selectable and copy-pasteable exactly as it appears in the PDF.

The search bar is tied to the text layer — it is only available when `textLayer` is enabled.
Search is debounced (220 ms) and highlights all matches on every rendered page simultaneously.
Matches on un-rendered (off-screen) pages are highlighted when those pages scroll into view.

---

## Virtualization

Only pages whose bounding box overlaps the visible viewport are rendered to canvas. Off-screen
pages are represented by empty `<div>` placeholders that match the page's exact pixel height,
so the scrollbar accurately reflects the full document length.

For **mixed-size PDFs** (A4 and A3 pages, for example), each page measures itself on first render
and reports its dimensions back to the container via an `onMeasure` callback. Cumulative offsets
are then recomputed, keeping `scrollToPage` accurate even when page sizes differ.

The `overscan` prop (default `2`) controls how many extra pages are rendered above and below the
visible area. Increase it if you see blank flash on fast scrolls; decrease it to reduce memory use.

---

## Worker configuration

pdfjs-dist ships a Web Worker for off-thread PDF decoding. By default the viewer injects a
version-pinned CDN worker URL. For air-gapped environments or strict CSPs, bundle the worker
yourself and point to it with the `workerSrc` prop:

```tsx
import workerUrl from 'pdfjs-dist/build/pdf.worker.min.mjs?url' // Vite

<PdfViewer source={bytes} workerSrc={workerUrl} />
```

## Recipes

### Display a file picked by the user

```tsx
const [file, setFile] = useState<File | null>(null)

<input
  type="file"
  accept=".pdf"
  onChange={(e) => setFile(e.target.files?.[0] ?? null)}
/>
{file && <PdfViewer source={file} />}
```

### Display a PDF fetched from an authenticated API

```tsx
const [bytes, setBytes] = useState<Uint8Array | null>(null)

useEffect(() => {
  fetch('/api/report.pdf', { headers: { Authorization: `Bearer ${token}` } })
    .then((r) => r.arrayBuffer())
    .then((buf) => setBytes(new Uint8Array(buf)))
}, [])

{bytes && <PdfViewer source={bytes} />}
```

### Embed without chrome (no toolbar, fixed size)

```tsx
<PdfViewer
  source={bytes}
  toolbar={false}
  textLayer={false}
  height={480}
  width={340}
/>
```

### Start on a specific page at a specific zoom

```tsx
<PdfViewer source={bytes} initialPage={5} zoom={1.5} />
```

---

## Caveats

- **SSR**: The component does not access `window` or `document` at module load time. The pdfjs-dist
  import is inside a `useEffect`, so server-side rendering is safe. Hydration renders a skeleton.
- **CSP**: The default CDN worker URL (`cdnjs.cloudflare.com`) must be allowed by your
  `worker-src` directive, or supply your own bundled worker via `workerSrc`.
- **Large PDFs**: For documents with hundreds of pages, set `textLayer={false}` until the user
  explicitly requests search — the text layer multiplies DOM node count significantly.

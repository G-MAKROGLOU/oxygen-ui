# AI Toolchain

OxygenUI ships a built-in MCP server and Claude Code integration so AI assistants can look up component APIs, search by use-case, and scaffold new work, all grounded in the actual documentation you're reading now.

---

## Architecture

```
Netlify deploy
├── /                     → Storybook static build (this site)
└── /mcp                  → netlify/functions/mcp.mts
                             Stateless HTTP, no session state
                             Data: netlify/functions/ai-manifest.json
                             Built by: node scripts/generate-ai-manifest.mjs
```

The manifest generator scans all 101 MDX guide files, strips Storybook boilerplate, and emits a single JSON file bundled into the function via esbuild. No database, no cold-start penalty.

## Context skill

The `/oxygen-ui` skill (`.claude/skills/oxygen-ui/SKILL.md`) loads the full design system context into any Claude Code session, import patterns, token usage, Tailwind utilities, form API, and repository conventions. Invoke it at the start of any session where you plan to build against `@geomak/ui`.

## Setup

### Remote server (after deploy)

Update `.mcp.json` with your Netlify site URL:

```json
{
  "mcpServers": {
    "oxygen-ui": {
      "type": "http",
      "url": "https://your-site.netlify.app/mcp"
    }
  }
}
```

Or via the CLI: `claude mcp add oxygen-ui --transport http https://your-site.netlify.app/mcp`

### Local server

```bash
npm install -g netlify-cli
yarn mcp:dev              # generates manifest + starts netlify dev on port 8888
```

The `oxygen-ui-local` entry in `.mcp.json` points to `http://localhost:8888/mcp` and is picked up automatically.

### Regenerating the manifest

When component docs change (new MDX files, updated props tables):

```bash
yarn generate-manifest
```

The Netlify build command runs this automatically before `storybook build`, so the deployed server is always in sync.

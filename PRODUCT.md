# Product

## Register

product

## Users

React developers building modern web applications — dashboards, SaaS tools, internal platforms, maritime and industrial software. They install the package from npm, integrate it with their own Tailwind config, and expect components that work out of the box with zero visual apology. They are building professional products and need a system that matches that ambition.

## Product Purpose

`@geomak/ui` is an open-source React component library for production-grade applications. It provides accessible, animated, and themeable primitives built on Radix UI and Tailwind CSS. It exists because most component libraries are either too opinionated (MUI, Ant Design) or too bare (headless-only). This sits in between: fully styled, fully overridable, with a strong visual identity that doesn't look like every other Tailwind project.

Success looks like: a developer installs the package, drops in a Button or Modal, and thinks "this looks like it belongs in a real product."

## Brand Personality

Bold, expressive, modern. The system has a point of view — it doesn't hedge. Animations are purposeful and fluid. Typography has presence. Components feel alive, not static. The tone is confident without being loud.

## Anti-references

- **Bootstrap / dated enterprise**: boxy borders, low contrast, flat gray palette, heavy shadows, desktop-only thinking. The visual language of 2012.
- **MUI bloat**: elevation-everywhere, ripple effects, dense components that feel like a framework fighting you.
- **shadcn/Tailwind defaults**: the slate-gray monoculture. If it looks like it could have been generated by `npx shadcn-ui init`, it has failed.

## Design Principles

1. **Earn the space.** Every component justifies its visual weight. Nothing is decorative by default — animation, color, and shadow all carry meaning.
2. **Motion is a material.** Transitions and animations are not polish applied at the end. They are part of the component's character from the start.
3. **Opinionated, not rigid.** Components have strong defaults that look great immediately, but every token is overridable. The system guides without trapping.
4. **Mobile is not an afterthought.** Touch targets, responsive layouts, and fluid type are table stakes — not a separate pass.
5. **Accessible by construction.** Radix primitives handle the behavior layer. The visual layer never undermines it.

## Accessibility & Inclusion

WCAG 2.1 AA minimum. Keyboard navigation on all interactive components via Radix. Reduced-motion support via `prefers-reduced-motion` — all Framer Motion animations respect it. Color contrast ratios enforced at the token level.
